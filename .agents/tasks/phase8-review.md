## Blocking findings

### P8-006 — Explicit sensitive questions still reach the LLM

`is_sensitive_question` still relies on finite substring and question-shape lists (`src/jobpilot/forms/base.py:202-624`). A narrow check returned `False` for “Are you allowed to work in the United Kingdom?”, “What hourly rate are you seeking?”, “Have you ever been found liable in a civil proceeding?”, and “Select your racial background”. These are explicit work-authorization, salary, legal/background, and demographic questions covered by R15.5. When no bank pattern happens to match, `resolve_question` falls through to `_answer_with_llm` (`src/jobpilot/forms/base.py:1718-1733`); the prompt instruction is not a code guard, and `FormAnswer.answer` requires a non-empty value (`src/jobpilot/llm/schemas.py:34-47`). The LLM can therefore fill protected answers. Route these category variants conservatively to the bank-only-or-blank path and add zero-LLM regressions for them.

### P8-010 — Real radio labels and required-group state are still modeled incorrectly

`_radio_options` records each radio’s submit value as both its label and value, without reading the associated visible `<label>` (`src/jobpilot/forms/base.py:834-852`). Thus a normal approved bank answer such as `No` cannot match options whose visible labels are `Yes`/`No` but submit values are `true`/`false`; the narrow option-match check returned `None`. Required-group validation also calls `_control_is_complete` on the single radio returned by `container.query_selector` (`src/jobpilot/forms/base.py:955-979`) and separately treats DOM `[required]` controls as individual controls (`src/jobpilot/forms/base.py:982-1000`). In real HTML, selecting a sibling does not make the first radio’s `is_checked()` true. The fake masks this by creating a group-like pseudo-control whose checked state is true when any sibling selector was checked (`tests/fakes.py:703-709`, `tests/fakes.py:780-805`). A usable approved answer can therefore remain blank, or a correctly selected required radio group can still abort. Resolve associated label text for every radio, retain label/value/selector separately, and validate required radios once per `name` group by checking whether any real member is selected; update the fake and regressions to expose actual sibling handles and distinct labels/values.

### P8-013 — A CAPTCHA detected after the click releases an ambiguous submit claim

The final click is dispatched at `src/jobpilot/forms/base.py:1383`, after which `_verify_post_submit` raises `CaptchaError` if a challenge appears (`src/jobpilot/forms/base.py:1397-1410`). `apply_via_form` releases the durable claim for every `CaptchaError` from `submit` (`src/jobpilot/forms/apply.py:297-301`). A post-click challenge does not prove that the remote form rejected the already-dispatched submission; the site may have accepted it before presenting the challenge. Releasing the claim lets a later explicit retry click again and create a duplicate application. Keep stopping and notifying for the CAPTCHA, but classify any challenge first observed after click dispatch as an ambiguous outcome and retain the claim for manual reconciliation. Release only a CAPTCHA found before dispatch or another outcome that proves non-acceptance.

### P8-014 — Browser interaction failures during filling bypass the required safe-abort notification

After initial marker checks, `fill_page` performs profile fills, uploads, and question interactions directly (`src/jobpilot/forms/base.py:1270-1300`). A normal Playwright failure caused by a detached/re-rendered control in `page.fill`, `set_input_files`, `select_option`, or `check` is not converted to `FormStructureError`. The reachable local caller catches only `CaptchaError` and `FormStructureError` around `active_filler.fill_page` (`src/jobpilot/forms/apply.py:265-273`), so such an unexpected-DOM failure escapes, the browser closes, and the CLI only prints `apply-form failed`; no abort screenshot or Telegram notification is produced. This violates R15.7’s required screenshot-and-notify behavior for unexpected structure. Convert pre-submit Playwright interaction/DOM errors into the safe-abort path while the page is still open, preserving the no-click behavior and sending the screenshot and notification.
